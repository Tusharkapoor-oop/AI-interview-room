5. EYE TRACKING — THE SCIENCE OF GAZE-BASED DETECTION
5.1 MediaPipe Iris + Kalman Filter — The Production Architecture
The dominant eye-tracking pipeline for browser-based proctoring combines Google MediaPipe FaceMesh (468 3D facial
landmarks) with MediaPipe Iris (iris, pupil, and eye contour) and a Kalman Filter for temporal smoothing. This pipeline runs
entirely on the candidate's device via WebAssembly/WebGPU, achieving sub-30ms latency without any server round-trip.
COMPONENT
SPECIFICATION
PROCTORING APPLICATION
MediaPipe FaceMesh
468 3D facial landmarks; 30ms latency on CPU; runs via WebGL in browser
Base layer for all gaze and pose analysis; provides dense eye region mesh
MediaPipe Iris Model
Iris, pupil, and eye contour landmarks; trained on ~50,000 manually annotated images; diverse illumination and head poses
Precise pupil center tracking; depth estimation via constant iris diameter (11.7 +/- 0.5mm)
Kalman Filter (2D State)
Models gaze vector position and velocity; predicts next gaze direction from previous state; accounts for measurement noise
Eliminates jitter from natural micro-saccades; smooths trajectory for pattern analysis; enables 97.5% accuracy in controlled conditions
L2CS-Net (Alternative)
Joint classification-regression; outputs pitch and yaw as continuous angles; ~50ms latency; maps to screen coordinates via MLP
Independent gaze vector computation regardless of head pose; critical for discrepancy analysis
Depth Estimation
(Pinhole Model)
d = (real_iris_width * focal_length) / iris_pixel_width; <10% relative error; no depth sensor required
Normalizes gaze estimates for candidates who shift position; corrects for varying distance from camera
5.2 The Deviation Angle Formula and Proctoring Application
The core gaze detection algorithm computes the deviation angle between the eye gaze vector and the camera center axis:
theta = arccos( (G_vec . C_vec) / (|G_vec| * |C_vec|) )
Where G_vec is the gaze direction vector derived from iris landmarks and C_vec is the camera axis vector. A deviation
exceeding 25 degrees triggers a cheating alert, but the system requires this threshold to be exceeded for 3+ consecutive
frames to reduce false positives from natural eye movements. The Kalman-filtered hybrid achieves 97.5% accuracy in
controlled environments, dropping to 92.3% in low-light and 85.2% under head motion — still above the 80% operational
threshold.

5.6 Statistical Baseline Deviation — The KS-Test Implementation
The critical upgrade from commercial systems: replace raw threshold-based gaze flags (if angle > 25° for 3 frames = flag)
with per-candidate statistical baseline modeling using the Kolmogorov-Smirnov test. This is documented in literature but
implemented in no open-source proctoring pipeline.
Implementation Steps:
1. CALIBRATION PHASE (first 90 seconds): Collect candidate's natural gaze distribution. Build baseline gaze point cloud.
Record natural fixation patterns, entropy levels, saccade velocities.
2. CONTINUOUS MONITORING: Collect rolling 10-second gaze windows throughout interview.
3. KS-TEST APPLICATION: Apply two-sample Kolmogorov-Smirnov test comparing active window distribution against
personal baseline. Flag ONLY when distribution shift is statistically significant: p < 0.05.
4. CONTEXTUAL SUPPRESSION: If candidate is responding verbally (audio activity detected), suppress gaze flags for
natural cognitive drift. Flag only when gaze deviation coincides with sustained silence OR with AI-phrasing detected in
concurrent speech analysis.
5. FUSION: Combine KS-test flag with other channels. Require 3+ concurrent channel deviations before raising integrity
event.
Why this matters: A candidate with naturally wandering eyes will never be flagged because their active
distribution matches their personal baseline. A candidate reading from an overlay will show a statistically
significant shift to low-entropy, directionally concentrated gaze — regardless of where their eyes naturally
wander when thinking.

10. WHAT EXISTING SYSTEMS MISS — THE 5 UNSOLVED PROBLEMS
This section identifies the five critical gaps in current commercial and academic proctoring systems. These are the areas
where the arms race is actively being lost — and where novel research contributions can establish genuine advancement
over the state of the art.
GAP 1
Compositor-Level Overlay Detection
PROBLEM:
Cluely and similar tools render below the WebRTC capture layer at the OS compositor level. No current
webcam-based, browser-based, or screen-capture-based system can detect these overlays directly. The only
indirect signal is whitespace fixation — candidates using overlays fixate on UI whitespace where no content
exists. This signal has never been implemented in a published proctoring pipeline.
SOLUTION:
Whitespace fixation detection via UI content zone mapping + gaze density KDE analysis. Candidate's eyes
should never concentrate on blank margins. This is the ONLY webcam-detectable Cluely signal available today.
GAP 2
Per-Candidate Statistical Gaze Modeling vs. Universal Thresholds
PROBLEM:
Every commercial system uses universal thresholds: angle > 25 degrees for 3 frames = flag. This produces high
false-positive rates for candidates with naturally wandering eyes, medical conditions, or cultural differences in
eye contact norms. The result is either high false positives or under-sensitivity.
SOLUTION:
KS-test based per-candidate baseline deviation. Build candidate's gaze distribution in first 90 seconds. Flag only
when active window distribution significantly deviates from personal baseline (p < 0.05). Zero published
implementations exist.
GAP 3
Combined PLR + rPPG Single Liveness Check
PROBLEM:
Commercial systems use PLR OR rPPG, never both in a single integrated check. CAST achieves 99.49% AUC
on known deepfake datasets but drops 25 points on unseen data. The fundamental problem is that detection
systems are reactive — they recognize known deepfake styles. Physiological signals (PLR + rPPG) are proactive
— they detect the absence of biology.
SOLUTION:
10-second combined check: screen flash triggers PLR while continuous rPPG monitors heartbeat. Both signals
must be present and physiologically consistent. No published paper demonstrates this combination in a single
RGB webcam check.
GAP 4
Cross-Dataset Deepfake Generalization
PROBLEM:
CAST drops from 99.49% (FF++) to 74.92% (Celeb-DF). The generalization gap means that new deepfake styles
— particularly those using novel backbone architectures or trained on different data distributions — evade current
detectors entirely until training data catches up. This is a fundamental limitation of pixel-artifact detection
approaches.
SOLUTION:
Challenge-response (Gotcha system) is the most promising direction: making deepfake generation fail rather
than detecting its output. FaceGraphNet's geometric constraint approach (facial geometry proportions that
deepfakes violate) shows better generalization than pixel-based methods.
GAP 5
Five-Channel Behavioral Consistency Fusion
PROBLEM:
Individual channels (gaze, gesture, audio, keystroke, content) each have 15-25% false negative rates when used
alone. Commercial systems stack independent checks without statistical fusion — a candidate just needs to
evade one channel. The fusion layer that requires 3+ simultaneous channel deviations with statistical significance
is described in academic literature but not implemented in any open-source pipeline.
