SECTION 1
HOW THIS WORKS — THE DEFENSE PHILOSOPHY
The Core Principle
Every bypass tool — whether a browser extension, a background daemon, or a hardware device — has to do three things to help a
candidate cheat: (1) capture the question or context, (2) generate or relay an answer, and (3) deliver that answer to the candidate
without the interview room detecting it. Your defense does not need to identify every individual tool by name. It needs to make every
step of that three-step chain detectable. This is why a tool-by-tool blocklist always loses the arms race — new tools appear weekly. A
chain-of-evidence defense, which detects the CAPTURE, RELAY, or DELIVERY step regardless of which tool performs it, never
goes obsolete.
The Three-Step Chain Every Bypass Tool Must Complete
STEP
WHAT THE TOOL MUST DO
WHERE YOUR DEFENSE LIVES
DETECTION CHANNEL
1. CAPTURE
Read the question — via OCR screenshot, audio transcription, DOM scraping, or screen-share interception.
Browser API layer + audio channel monitoring
Screen Capture API enumeration; Web Speech API usage detection; DOM read-access auditing
2. RELAY
Send captured content to an answer source — local LLM, cloud API, or human proxy — and receive a response.
Network layer + process layer
WebSocket/fetch destination monitoring; outbound connection fingerprinting; local process enumeration
3. DELIVERY
Get the answer to the candidate — compositor overlay, DOM injection, audio earpiece, or visual wearable.
Visual layer (gaze) + Physical layer (gesture/posture) + DOM layer
Whitespace fixation; gaze-pose discrepancy; hand-to-ear gesture; DOM mutation observer; clipboard interception
WHY THIS MATTERS FOR YOUR INTERVIEW ROOM: A new cheating extension launches next month. If your defense
is a blocklist of known extension IDs, you are already behind. If your defense monitors the
CAPTURE/RELAY/DELIVERY chain itself, the new extension is caught automatically because it still has to capture,
relay, and deliver — there is no fourth way to cheat. Every countermeasure in Section 3 is built on this principle.

IMPLEMENTATION
WHAT IT CATCHES
RESIDUAL RISK
Whitespace Fixation
Detection
UI layout coordinate extraction + gaze vector zone classification + KDE density estimation. Flag if ws_ratio>0.35 with KDE peak in whitespace zone.
ANY tool that delivers content via invisible overlay, regardless of the specific tool's name or rendering technique — because all overlay tools require the candidate to look at the area where the overlay renders.
None identified — this is a geometric/behavioral signal independent of the overlay's rendering technology.
Gaze-Speech Temporal

Cross-reference gaze pattern classification (reading vs. thinking) against simultaneous audio activity. Flag if mechanical L-R saccade pattern occurs WHILE candidate is speaking fluently.
Reading from any hidden text source while answering — independent of whether the text is rendered via compositor overlay, second monitor, or printed notes.

Known and forked Cluely variants by process behavior signature, even after process name obfuscation, via behavioral fingerprinting (CPU/GPU usage pattern, screenshot API call frequency).
Browser-only deployments cannot enumerate OS processes — this layer requires a desktop client or browser extension with elevated permissions.

DEFENSE LAYER

WebSocket / Fetch
Destination Monitoring
Service Worker network interceptor logs all outbound connections during the interview session. Maintain a continuously-updated blocklist of known LLM API domains (api.openai.com, claude.ai, gemini.google.com, and pattern-match for new LLM provider domains).

Any tool that injects an answer into the page DOM — this includes browser-tab copilots, extension-based overlays, and console-injected content.

Candidates manually alternating between the interview and a disguised documentation-style tab running a copilot tool.
Tools using a SEPARATE PHYSICAL DEVICE (not a browser tab) for relay are not caught by this browser-level signal — covered by gesture/posture layers in Section 5.

IMPLEMENTATION

Extension Enumeration
(chrome.management API)
With explicit candidate consent at session start, request the chrome.management permission to enumerate installed extensions. Cross-reference installed extension IDs against a maintained blocklist of known cheating-tool extension signatures. Require disabling flagged extensions before the session can begin.

Local LLM extensions that evade network monitoring, caught instead via their DOM injection behavior.
Sophisticated extensions using Canvas rendering instead of DOM text injection could partially evade — closed by whitespace fixation gaze detection (3.1).

Camera Hardware
Metadata Verification
At session start, query MediaDevices.enumerateDevices() and cross-reference camera device labels and capabilities against known virtual camera driver signatures (OBS Virtual Camera, Snap Camera, ManyCam). Physical cameras report consistent hardware-specific metadata that virtual drivers cannot perfectly replicate.
OBS VirtualCam, Snap Camera, and similar virtual camera drivers used to inject pre-recorded or deepfake video instead of a live feed.
Sophisticated actors can spoof device metadata; this is why metadata verification is layer 1, with PLR+rPPG physiological liveness as the definitive layer 2 (Section 5).
PLR + rPPG Combined
Liveness (Definitive Layer)
As detailed in the AEGIS ULTRA framework: randomized screen-brightness PLR check + continuous rPPG heartbeat extraction. A virtual camera feeding pre-recorded or synthetic video CANNOT produce a live, synchronized physiological response.
ALL virtual camera content regardless of source — pre-recorded video, deepfake, photo, or mask — because this checks for biological signals no injected video can fake in real time.
This is the strongest available countermeasure; no demonstrated bypass exists for a properly randomized, server-validated PLR+rPPG check.
Selective Screen-Share
Window Enumeration
Use the Screen Capture API's getDisplayMedia() with surfaceSwitching disabled, and cross-reference the shared source against the full window enumeration via the Window Management API to detect if other windows are open but unshared.
Candidates who screen-share only a specific window while running a cheating tool in an unshared window on the same screen.
Cannot detect content on a genuinely separate physical monitor not captured by any screen-share — covered by gaze/posture detection of off-screen looking.

3.6 Countermeasure: Clipboard and DOM Injection
DEFENSE LAYER
IMPLEMENTATION
WHAT IT CATCHES
RESIDUAL RISK
Clipboard Event
Interception
Intercept all `paste` events on code editor and text input fields. Log pasted content length, timing, and source. Flag any paste event into a code/answer field exceeding 50 characters.
Direct clipboard paste of pre-prepared or externally-generated answers into the interview interface — this is mandatory infrastructure for clipboard-based cheating regardless of how the clipboard content was generated.
None for the paste vector itself; candidates could still RETYPE pre-prepared content manually — covered by burst-typing and keystroke-rhythm detection instead.
DOM Direct-Assignment
Detection
Override and monitor the native `value` property setter and `execCommand` on all input/textarea/contenteditable elements within the interview interface using a defineProperty interceptor, to detect programmatic value assignment that bypasses normal keyboard events.
Direct JavaScript console or extension-based DOM value injection that completely bypasses both keyboard events AND the paste event.
Requires the interceptor to be installed before any malicious script runs — achieved by injecting the interceptor as the very first script in page load order.
Keystroke-Content
Reconciliation
Continuously reconstruct expected content from the logged keystroke event stream and diff it against actual field content every 500ms. Any divergence (more content present than keystrokes account for) is logged as definitive injection regardless of the injection method used.
ANY injection method whatsoever — clipboard, DOM assignment, console script, or extension — because this is a content-vs-input-event reconciliation check independent of the specific injection technique.
This is the most comprehensive single defense against all injection methods; no residual risk identified for content injection specifically.

SECTION 4
THE BROWSER LOCKDOWN STACK — NATIVE IMPLEMENTATION
This is the complete, layered implementation that combines every countermeasure from Section 3 into a single JavaScript module
you load at the start of every interview session. Each layer is independent — if one is bypassed, the others still run.
4.1 Session Initialization Sequence
// AEGIS SHIELD — Core Initialization (runs first, before any other script)
class AegisShield {
constructor(sessionId) {
this.sessionId = sessionId;
this.flags = [];
this.keystrokeLog = [];
this.domBaseline = new Map();
this.checksum = this.computeSelfChecksum();
}
async initialize() {
await this.requestExtensionEnumeration(); // 3.3
await this.verifyCameraHardware(); // 3.4
this.installClipboardInterceptor(); // 3.6
this.installDOMValueInterceptor(); // 3.6
this.installMutationObserver(); // 3.2
this.installNetworkMonitor(); // 3.2
this.installDevToolsDetector(); // 3.7-3.8
this.installFocusVisibilityLogger(); // 3.2
this.installKeystrokeReconciliation(); // 3.6
this.startIntegrityHeartbeat(2000); // self-check every 2s
}
}
4.2 Extension Enumeration Module
async requestExtensionEnumeration() {
// Requires candidate consent (browser privacy model)
const consent = await this.showConsentDialog(
'To verify a secure testing environment, please allow extension scan.');
if (!consent) {
this.flag('EXTENSION_SCAN_DECLINED', severity=3);
return;
}
chrome.management.getAll((extensions) => {
const blocklist = this.loadExtensionBlocklist(); // updated server-side daily
for (const ext of extensions) {
if (ext.enabled && blocklist.has(ext.id)) {
this.requireDisable(ext.id, ext.name);
this.flag('KNOWN_CHEAT_EXTENSION', severity=5, evidence={id: ext.id, name: ext.name});
}
// Heuristic: flag unknown extensions with broad host permissions
if (ext.enabled && this.hasOverlyBroadPermissions(ext)) {
this.flag('SUSPICIOUS_EXTENSION_PERMISSIONS', severity=2, evidence={id: ext.id});
}
}
});

4.3 Network and DOM Monitoring Module
installNetworkMonitor() {
const KNOWN_LLM_DOMAINS = [
'api.openai.com', 'claude.ai', 'anthropic.com', 'gemini.google.com',
'api.cohere.ai', 'openrouter.ai' /* pattern-matched, list server-updated */
];
navigator.serviceWorker.addEventListener('fetch', (event) => {
const url = new URL(event.request.url);
if (KNOWN_LLM_DOMAINS.some(d => url.hostname.includes(d))) {
this.flag('LLM_ENDPOINT_CONNECTION', severity=5, evidence={url: url.hostname});
}
});
}
installMutationObserver() {
const observer = new MutationObserver((mutations) => {
for (const m of mutations) {
const delta = this.computeTextDelta(m);
const recentKeystrokes = this.keystrokeLog.filter(
k => Date.now() - k.timestamp < 2000).length;
if (delta > 100 && recentKeystrokes === 0) {
this.flag('DOM_INJECTION_NO_KEYSTROKES', severity=5,
evidence={delta, recentKeystrokes});
}
}
});
observer.observe(document.body, {childList:true, subtree:true, characterData:true});
}
4.4 Clipboard, DOM-Value, and DevTools Interceptors
installClipboardInterceptor() {
document.addEventListener('paste', (e) => {
const text = e.clipboardData.getData('text');
if (text.length > 50 && this.isAnswerField(e.target)) {
this.flag('CLIPBOARD_PASTE_LARGE', severity=4, evidence={length: text.length});
}
}, true);
}
installDOMValueInterceptor() {
const nativeSetter = Object.getOwnPropertyDescriptor(
HTMLInputElement.prototype, 'value').set;
Object.defineProperty(HTMLInputElement.prototype, 'value', {
set: function(val) {
if (!window.__aegisLastKeyEvent ||
Date.now() - window.__aegisLastKeyEvent > 100) {
aegisShield.flag('DOM_DIRECT_VALUE_INJECTION', severity=5,
evidence={length: val.length});
}
nativeSetter.call(this, val);
}

SECTION 5

5.1 Architecture: Gesture as a First-Class System, Not a Bolt-On
Most interview rooms add gesture detection as an afterthought — a separate script that occasionally checks for obvious problems.
AEGIS SHIELD treats gesture, eye tracking, and posture as a single unified perception system that runs continuously at 30 FPS for
the entire interview and is wired directly into the same flag/fusion engine as the browser lockdown stack from Section 4. This means
a gesture flag and a DOM injection flag can combine in the SAME fusion event — for example, hand-to-ear gesture + LLM endpoint
connection in the same 10-second window is a much stronger signal than either alone.

evaluateFlags(features, window, baseline) {
const gazeFlag = this.checkGazeKS(window, baseline); // KS-test, p<0.05
const wsFlag = this.checkWhitespace(window); // ws_ratio>0.35
const gestureFlag = this.checkGestureSignatures(features); // hand-to-ear, off-cam
const postureFlag = this.checkPostureSignatures(features); // shoulder, spine, FFT

const activeChannels = [gazeFlag, wsFlag, gestureFlag, postureFlag,
livenessFlag, ...browserFlags].filter(f => f.active);
const N = activeChannels.length;
if (N >= 5) this.shield.raiseEvent('CRITICAL', activeChannels); // pause + human review

// N <= 1: never raised — single-channel flags are statistically too noisy
}
